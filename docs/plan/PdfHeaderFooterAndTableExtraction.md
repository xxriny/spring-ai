# PDF 반복 머리말·꼬리말 제거와 표 색인 설계

## 목적과 범위

PDF를 색인할 때 여러 페이지에 반복되는 머리말·꼬리말을 제거하고, 표의 열과 행 관계를 보존한다. 첫 적용 대상은 텍스트가 포함된 PDF다. 생성 모델이 정해지지 않았으므로 표 요약을 위한 LLM 호출은 하지 않고 표를 Markdown으로 변환해 임베딩한다. HTML과 Word 표, 이미지로만 된 PDF의 표 구조 인식은 이번 범위에 포함하지 않는다. 이미지 PDF의 기존 OCR 텍스트 추출은 유지한다.

## 선택한 방식

현재 Java `PDFTextStripper`는 페이지 텍스트만 반환해 표의 좌표·셀 경계를 잃는다. 로컬 Python OCR 서버에 PDF 추출 경로를 추가하고 `pdfplumber`로 페이지의 텍스트 위치와 표 셀을 읽는다. Spring Boot `KnowledgeService`는 추출 결과를 받아 본문과 표 행을 별도 `Document`로 만든 뒤 기존 청크 분할·임베딩·pgvector 적재를 사용한다. Java에서 PDFBox 좌표 해석기를 새로 작성하는 방식은 표 병합 셀 처리 범위가 커서 선택하지 않았다.

텍스트 PDF 등록에는 로컬 추출 서버가 필요하다. 서버 오류나 형식이 맞지 않는 응답이 오면 등록을 실패시키고 기존 URL 색인을 유지한다. 표가 감지되지 않거나 행을 추출하지 못한 영역은 일반 본문 텍스트로 색인한다. 반복 머리말·꼬리말 제거 후 본문과 추출된 표 행이 모두 없는 페이지는 기존 OCR 경로로 전달한다.

## 추출 규칙

1. 페이지마다 표의 경계 상자와 셀을 찾는다. 표 안의 글자는 일반 본문에서 제외해 중복 색인을 막는다.
2. 각 페이지 상단·하단 10% 영역의 텍스트 줄을 정규화해 비교한다. 같은 줄이 적어도 2쪽이면서 전체 페이지의 60% 이상에 나타날 때만 반복 머리말·꼬리말로 판단한다. 본문 중간의 동일 문구는 제거하지 않는다. 페이지 번호처럼 숫자만 바뀌는 줄은 페이지 가장자리에서만 별도로 정규화한다.
3. 표의 열 제목을 각 행에 반복한 Markdown 표로 변환한다. 셀 안의 줄바꿈은 `<br>`로, `|`는 이스케이프 처리한다. 실제로 병합된 셀의 값만 해당 행에 이어 붙인다. 열 제목을 신뢰할 수 없으면 임의 제목을 만들지 않고 원래 셀 텍스트를 보존하며 추출 상태를 기록한다.
4. 각 논리 행을 독립된 문서로 색인한다. 긴 행은 열 제목과 행 식별 정보를 각 청크에 유지하면서 800토큰 이하로 나눈다. 일반 본문에는 현행 최대 800토큰·최대 100토큰 오버랩을 적용한다. 페이지와 표 행 사이에는 오버랩을 만들지 않는다.

## 데이터와 경계

- Python 서버는 최대 20MB PDF 바이트를 받아 페이지별 `body`와 `tables`를 반환한다. 표에는 페이지 번호, 표 번호, 행 번호, Markdown 텍스트, 추출 상태가 포함된다. 입력과 출력에 원본 문서나 API 비밀값을 로그로 기록하지 않는다.
- pgvector 청크 메타데이터의 기존 `documentId`, `scope`, `ownerId`, `title`, `source`, `category`, `chunkOrder`, `page_number`를 유지한다. 표 청크에는 `contentType=TABLE_ROW`, `tableIndex`, `rowIndex`, `tableExtractionStatus`를 추가하고 본문에는 `contentType=BODY`를 추가한다. API 응답의 기존 필드는 유지한다.
- 검색 점수와 Top-k는 현행 `RetrievalService`의 `topK(10)`·유사도 기준 `0.3`·Qwen 재정렬을 그대로 사용한다. 이 작업은 ETL만 바꾼다.
- 기존에 적재된 문서는 자동 변경되지 않는다. 같은 URL의 동일 바이트 재수집은 건너뛰므로 삭제 후 재등록해야 한다. 재등록에는 OpenAI 임베딩 호출이 발생한다.

## 검증 기준

- 반복 머리말·꼬리말은 제거되고, 한 번만 나타나는 상단 제목과 하단 주석은 남는다.
- 표의 열 제목, 행별 셀 관계, 병합 셀 값이 Markdown 청크에 유지되며 일반 본문에 표 텍스트가 중복되지 않는다.
- 표가 없는 PDF와 OCR 페이지는 기존 추출 결과를 잃지 않는다.
- Python 추출기 단위 테스트와 Java 서비스 경계 테스트를 실패 상태에서 먼저 작성한다. 표가 있는 샘플 PDF는 읽기 전용으로 추출 결과를 점검한다. 외부 임베딩 API를 호출하는 실색인 검증은 비용 상한을 정해 승인받은 뒤 별도로 실행한다.

## 한계

표 선이 없거나 열 정렬이 불명확한 PDF는 표를 감지하지 못할 수 있다. 이런 페이지는 본문 텍스트를 보존하되 표 구조가 복원됐다고 표시하지 않는다. 스캔 PDF의 표 구조를 복원하려면 별도 레이아웃 인식 모델이 필요하다.
