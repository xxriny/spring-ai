# 현재 구현 범위 (v0.1.0)

## 지원 기능

- 로컬 `admin`과 `user` 계정으로 로그인한다. 관리자는 공용 문서를 등록·삭제하고 URL을 수집한다. 사용자는 본인 문서를 등록·삭제한다. 대화는 공용 문서(`SHARED`) 또는 내 문서(`PRIVATE`) 중 한 범위로 시작하며, 범위를 바꾸면 새 대화를 만든다.
- TXT, PDF, DOC, DOCX, HTML/HTM 파일을 최대 20MB까지 등록한다. 관리자 URL 수집은 시작 페이지와 같은 스킴·호스트·경로 하위의 HTML과 링크된 TXT/PDF/DOC/DOCX를 최대 100쪽까지 처리한다. 동일 URL·동일 내용은 건너뛰고 변경된 문서는 재색인한다.
- TXT·Word·HTML 본문을 추출한다. HTML은 중첩 요소와 제목·본문이 같은 절의 중복을 제거한다. PDF는 반복 머리말·꼬리말을 제거하고 표 행을 Markdown으로 별도 추출하며, 추출 후 텍스트가 없는 페이지는 로컬 PaddleOCR 한국어 PP-OCRv5로 읽는다.
- 본문을 최대 800토큰 청크로 나누며, 같은 페이지·구간의 인접 본문 청크에 이전 청크 최대 100토큰을 겹친다. 표 행에는 오버랩을 적용하지 않는다. Ollama `qwen3-embedding:8b`의 1536차원 임베딩을 pgvector에 저장한다. 등록 시 카테고리 1~80자를 입력한다.
- 접근 가능한 문서에서 pgvector Top-10(유사도 기준 0.3)과 `pg_search` BM25 Top-10을 검색한다. RRF(k=60)로 합친 상위 10개를 로컬 `Qwen/Qwen3-Reranker-0.6B`로 재정렬하고, 상위 3개 청크의 같은 문서·페이지 앞뒤를 확장해 passage당 최대 1,200토큰의 근거를 반환한다.
- 대화의 후속 질문은 Ollama `qwen3.5:9b`로 독립 검색어로 정리한다. 최종 passage를 근거로 답변하고 출처와 답변 조각을 NDJSON으로 전송한다. `MessageChatMemoryAdvisor`와 JDBC 메모리를 사용하며, 완료된 답변을 대화 기록에 저장한다. 독립 검색 API는 원문 질문 하나만 사용한다.
- 화면은 React·Vite 기반이며 딥블루 색상, 대화 목록, 본문, 참고 자료 패널을 제공한다.

검색 과정·데이터 모델은 [아키텍처](Architecture.md)와 [하이브리드 검색 명세](HybridRetrieval.md), HTTP 요청·응답은 [API 계약](ApiContract.md)을 따른다.

## 첫 버전 제한

- MultiQuery 확장, 키워드·요약 메타데이터 자동 생성, 모델 기반 passage 요약, 답변 품질 평가는 구현하거나 수행하지 않았다. PDF 표 구조를 확정할 수 없으면 텍스트를 본문에 보존한다. OCR은 텍스트가 없는 PDF 페이지에만 적용하며 Word·HTML 이미지와 표 구조 인식은 포함하지 않는다.
- URL 수집은 동기식이며 `robots.txt` 정책 처리, 예약 재수집, 작업 큐, 진행률은 없다. 외부 URL 등록 권한을 가진 관리자는 신뢰된 운영자여야 한다.
- 계정은 고정된 두 개뿐이다. 가입, 권한 위임, 운영용 감사 로그는 없다. 웹 서버는 Spring MVC이며 Reactor `Flux`를 이용한 답변 스트리밍만 제공한다. 검색·JDBC는 동기식이므로 첫 답변 조각은 검색·리랭킹 후 전송된다.
- 현재 CPU·256토큰 리랭커 설정으로 공식 문서 16문항을 재평가하지 않았다. 실측 기록은 [2026-10-23 평가](LocalRetrievalEvaluation2026-10-23.md)와 [2026-10-26 재색인 평가](LocalRetrievalEvaluation2026-10-26-ToBe.md)를 참고한다.
